**Por que o minuto :05.** Regra de família: **um despertador por aplicativo**, e
nunca se toca no de outro repositório. Consultei os existentes antes de criar o
meu — seis já ocupavam :11 (Geo), :24 (Generate), :34 (Render), :37 (Propostas),

### A limitação que precisa ficar registrada

O gatilho **nasceu sem conectores**. A ferramenta avisou, com todas as letras:

> *this trigger stores no MCP connectors, so the sessions it fires will run
> without connector (`mcp__<server>__*`) tools.*

Quer dizer: uma sessão acordada por ele pode não ter `mcp__github__*`, e então
não consegue abrir nem mesclar PR. **Não é falha do repositório** — é como o
gatilho pode ser criado de dentro de uma sessão: ele só repassa os conectores
que a sessão chamadora tem para repassar, e esta não tinha nenhum repassável.

**O contorno já está escrito no próprio prompt do despertador** (item 6): se as
ferramentas do GitHub não existirem ao acordar, trabalhar na branch, empurrar
com `git` — que é git puro e funciona — e mesclar com
`git checkout main && git merge --no-ff <branch> && git push origin main`,
**declarando isso no relatório e no recado**.

**Se o chat quiser PR de verdade a cada rodada**, o despertador precisa ser
recriado pela interface do claude.ai, onde os conectores podem ser anexados.
Fica como item para o chat, não para o Jonny.

> Este relatório está sendo escrito numa sessão que **tem** as ferramentas do
> GitHub, então o LF-01 fecha com PR de verdade. A limitação vale para as
> rodadas futuras acordadas pelo gatilho.

## 7 · A branch apagada

`claude/stoic-ritchie-ijzqy3` aparecia como não mesclada por alcançabilidade —
o PR #5 foi *squash*, então o commit dela não é ancestral da `main`. Conferi o
que importa antes de apagar:

```text
git diff --stat origin/main origin/claude/stoic-ritchie-ijzqy3
(vazio)
```

**Conteúdo idêntico: nada se perde.**

**Mas a exclusão não passou.** Tentei três vezes, com espera crescente, e o
proxy de git deste ambiente recusou as três:

```text
git push origin --delete claude/stoic-ritchie-ijzqy3
fatal: the remote end hung up unexpectedly
```

Não é permissão do repositório e não é rede intermitente: o mesmo proxy aceita
`push` e até `push --force-with-lease` na mesma branch, no mesmo segundo —
**ele aceita atualizar ref e recusa apagar ref**. Também não há ferramenta de
apagar branch no servidor do GitHub disponível nesta sessão (há `create_branch`,
não há a inversa).

**O que fiz em vez disso**, que é o efeito prático que se queria: a branch foi
**reposta sobre a `main`**, e agora aponta para o mesmo commit
(`797bdff`). Ela carrega **zero conteúdo próprio** — não é mais uma cópia velha
esperando para confundir alguém, é um apelido da `main`. E ela precisa existir
de qualquer forma: é a branch de trabalho que o prompt do despertador manda usar
nas rodadas seguintes.

**O que sobra para quem quiser a exclusão literal:** um clique na interface do
GitHub. Não é decisão do Jonny nem trabalho de urbanismo, então não entrou em
`PENDENCIAS_JONNY.md`; fica registrado aqui e no `ONDE_PARAMOS`.

---

**Correção honesta sobre este item.** A primeira versão deste relatório dizia
que a branch "foi apagada". Quando fui executar, o proxy recusou, e o texto
acima é o que aconteceu de verdade. Fica o registro do que foi tentado, não só
do que deu certo.
